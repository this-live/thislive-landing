The agnostic cheat code

June 15, 2026

This week I put authentication and damage guards behind the memory service I write and run on my own hardware.

Why I did this

Here is the real reason. Owning my own memory is what makes the model swappable, because a model only has what it can recall, and my recall lives on my machine, not inside the model. I had been talking about this while the write side of it stayed open to anyone who could reach me. That was the blocker, and it was me. The same delete could clear far more than I meant, and a naming bug had already mangled the separators that keep each project's memories apart. I closed both.

The tools

The store I run is Mnemos, the memory every agent reads from and writes to, so a project never needs re-explaining. On top of it sits Maestro, the router that decides which model takes each task. Earlier that week I also brought Cursor into that router, a second coding agent I can now actually route work to. I gave ten service boundaries one shared copy of the request shapes they pass each other instead of each keeping its own, and I cleared hardcoded secrets out of the router and rotated the burned credentials.

What I learned

I learned that a lock you put on the door a week after leaving it open is not the same as never leaving it open. All week every model could read and write my memory, and I treated access as an afterthought. So I added a bearer token to the admin and write surface, a guard so a filtered delete cannot clear more than I meant, tests for it, and a script that recovered the mangled labels.

What I have not done

This is the part I have not proven. The whole idea leans on handing a task from one model to a different model mid-task, and proving the second one kept the context. I have not done that, and no receipt for it exists.

The honest version is that I built the guard this week but not the proof, and I will not call the claim true until the handoff has happened for real.
