There was a daemon running on my main machine that nothing documented

August 17, 2026

I spent part of the week of 2026-08-17 writing a runbook for a daemon on my own main machine that no document described.

Jarvis is the workhorse. It runs the Hermes harness, the dispatch daemon, dictation, the local model plumbing and most of what I use during a day. Something on it was running as a long lived process that had never been written down. Not broken. Not misbehaving. Simply undocumented, which means that if it stopped, the only recovery procedure was my memory of a thing I had set up once.

What a runbook admits

Writing the runbook is an admission before it is a fix. It says this was running and I could not have told you how to restart it. The second Forge engineering note from the same day is the same kind of admission in a different register: a canon reference for the knowledge graph schema, written because the schema existed in working use and not in any reviewable place.

Real and synthetic

The learning loop got a smaller change with the same shape. Its exerciser now labels and archives synthetic sessions after every run, so the sessions it generates to test a skill cannot be mistaken later for sessions a person actually had. Receipts only mean something if you can tell which ones came from real use. Left alone for a few months, that distinction is the kind of thing that quietly poisons a reputation score.

Elsewhere the research scanner on BTC Finder kept its daily cadence and recorded a marketplace whose live listing count drifted from 443 down to 331 while its headline total stalled. That is what a stalling market looks like before anybody writes an article about it.

What I am not claiming

I am not going to claim the fleet is documented now. One runbook for one process on one machine is one item off a list I have never fully written, and the honest reason I wrote this one is that I noticed it, not that a process found it.

In three months I will tell you whether an inventory exists that would have found that daemon without me tripping over it.

Thanks for reading. The process you cannot hand to somebody else is the one to write down first.
