## 2026-09-12 — Landing: per-PR changelog fragments (no more CHANGELOG collisions) (U73)

- Problem: the global changelog-preflight pre-commit hook (`~/.agent-fabric-runtime/scripts/git-changelog-preflight.py`) requires a file named `CHANGELOG.md` in every commit's changed set for this repo. Every landing PR satisfied it by hand-inserting its entry at the very top of `CHANGELOG.md`. Two or more PRs open at once always inserted at the same anchor line, so every merge re-conflicted every other open PR — four rounds today, and Bryce could not merge them himself.
- Change: `CHANGELOG.history.md` — the pre-2026-09-12 content of `CHANGELOG.md`, moved byte-for-byte unchanged (verified via `diff`).
- Change: `changelog.d/<YYYY-MM-DD>-<slug>.md` — one fragment file per change going forward, containing the same entry text that used to be inserted at the top of `CHANGELOG.md`. Adding a fragment is a new, uniquely-named file, so two concurrent PRs' fragments never touch the same lines and can never conflict with each other.
- Change: `scripts/changelog-assemble.mjs` — dependency-free Node script that deterministically renders `CHANGELOG.md` from all `changelog.d/*.md` fragments (sorted newest-date-first, then slug) plus a link to `CHANGELOG.history.md`. Idempotent: running it twice with no fragment changes produces byte-identical output. `--check` exits non-zero if `CHANGELOG.md` is stale.
- Change: `.gitattributes` — added `CHANGELOG.md merge=union` as a second line of defense. Even in the pathological case where two PRs both regenerate `CHANGELOG.md` from a common base without seeing each other's new fragment (e.g. both are the first-ever fragment for a given day), git unions the added lines instead of raising a conflict; re-running the assembler afterward restores canonical order.
- Change: `README.md` — added "How to add a changelog entry" section documenting the fragment + assemble workflow.
- Reason: stop landing-site PRs from colliding on `CHANGELOG.md` (program plan row U73, 2026-09-12) without touching the global pre-commit hook, which lives outside this repo and guards other repos too.
- Verified: `node scripts/changelog-assemble.mjs` run twice in a row produces a byte-identical `CHANGELOG.md` (idempotency). Two throwaway branches cut from this PR's tip, each adding one different fragment and regenerating `CHANGELOG.md`, were merged with `git merge-tree` both directions and into main — all three merges were clean (no conflict markers, exit 0); full command output is in this PR's description.
- Rollback: revert this PR. `CHANGELOG.md` would need its pre-2026-09-12 top section restored from `CHANGELOG.history.md` by hand (or `git revert` the merge commit, which restores the prior single-file state exactly).
